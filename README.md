## 0.3.4 基础流程与百度设置

先更新配套平台，再覆盖安装。首页显示景区、设备、账号、规则、平台配置、人员/回执进度及最近同步时间。未取得完整平台信息、未完成同步或心跳过期时禁止开始核验。维护页“管理员设置”经联网密码验证后打开百度原生 SettingActivity；平台地址仍由“平台连接设置”修改。

进入百度设置会暂停相机与SDK同步；返回后重新读取配置，检测最小人脸、检测阈值、质量阈值、RGB活体阈值、识别阈值可供当前核验链路使用，重新开相机时读取摄像头ID。当前手机采用RGB活体、系统相机方向；Demo中的红外/深度、镜像角度、图像优化、Demo日志等界面仍属原生能力，尚未全部接入本核验链路，不能把可打开等同于已生效。关闭Demo活体或质量开关不会取消本核验端的强制检查。返回后须手动开始核验。

修复SDK返回单位：512字节特征缓冲区对应128个float；旧代码误把成功返回128当成失败。本版保留真正的SDK异常返回值，不将其伪装成照片质量失败。

## 0.3.5 权限与同步减负

首次进入显示权限说明，可授权相机；所有页面保留权限管理入口。拒绝或系统不再询问时可跳转应用设置，统计与同步不依赖相机权限。平台照片不读取手机相册，不要求相册/全部文件权限。

空闲心跳15–20秒、通信30秒；有任务3–4秒继续，失败5–65秒退避错峰。已存储的同用户/同版本特征重新放入原生检索成功后直接确认，不重复下载照片；换版本或删除后不能复用。人员来自平台任务队列，目前为增量拉取，尚未实现长连接推送。先更新平台，再覆盖安装APP。更多容量验证待办见需求台账。

0.3.7：交替测试可点击“下一位 / 重新核验”；不同已录入身份稳定匹配可触发新一轮，同一人需移开或手动重试。诊断显示实际活体/识别分数，业务结果区分本地未匹配与平台拒绝。共享人员库在后续0.4.0实现，见下节。

## 多设备安装包导出（0.7.2起）

在Windows仓库根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Export-Apk.ps1
```

复用现有正式签名，依次执行现有主机测试、Release构建、Lint、单元测试和签名验证，全部通过才导出。默认打开桌面`Yikatong-APK`下的新目录，含APK及`build-info.txt`（版本、SHA256、源码提交及是否有本地修改）。不要把`signing.properties`、签名密钥或SDK授权文件发送到测试设备。此脚本本轮尚未在Windows执行，成功打包不等于设备验收通过。

手机端“维护 → 设备诊断 → 导出诊断快照（TXT）”可导出当前运行状态；与同一时刻的故障截图、设备型号及复现步骤一起反馈。快照不含人员和访问凭据，不是完整运行日志，内存采样也不是峰值。

相机主机回归（需要Python 3和JDK）：`python tests/test_camera_lifecycle.py`。使用替身Android回调验证生命周期，不代替真机相机测试。

## 新设备激活错误1007（0.7.3）

此SDK封装中的1007表示尚未获取百度设备指纹，不是授权码绑定结论。0.7.3移除电话状态权限的Manifest合并声明、在激活前等待指纹初始化并区分失败原因。未激活页可直接导出诊断；不要复制其他设备的License，不要清除现有人员库和未确认记录。

0.7.3的`Build-Demo.ps1`还会检查最终APK权限，并写入与APK SHA256对应的构建验证标记。`Test-Device.ps1 -Install`需要该标记，不会安装失败构建遗留的旧APK；新机安装前会检查Android API≥21及ARMv7/ARM64架构。机型是否能获取SDK指纹、相机/语音是否可用仍须真机验证。
