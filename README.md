# 一卡通景区刷脸核验端

需求与完成情况请查看 [需求进度台账](docs/REQUIREMENTS-STATUS.md)，区分代码实现、部署与现场验收。

基于已提供的 FaceSDKAndroid(2).zip 完整 Demo 二次开发，包名 `com.lingluren.yikatong.terminal`，版本 `0.5.1-ui-layout`（112）。实际 APP 仓库为 `hliujies-hue/linglurenyikatongapp`。

`demo-local` 是原版，`demo-work` 是本地工作副本；`overlays` 保存维护代码。已有工作副本直接拉取并执行 `scripts/Build-Demo.ps1`，不要重新导入或清除签名、授权、应用数据。构建时自动应用覆盖文件。

本轮实现设备激活后的子账号登录、V2 自动登记、真实 SDK 图片转特征与本地检索、增量增删人脸、活体核验、平台业务判定、SQLite 事件和回执、断网失败补传、同步完成后退出，以及日期筛选的景区共享人数。硬件不固定绑定账号，子账号归属景区主账号，单点规则取子账号快照。

配套平台使用 `hliujies-hue/linglurenyikatong` 的 `codex/terminal-session-v2-20261013` 分支。0.4.0需要配套共享人员库平台更新，具体提交见本轮交付命令及需求台账。先更新平台，再构建和覆盖安装 APP。Git 使用 SSH，不自动运行 GitHub Actions。

已完成 Java 编译检查（Android 29 与所提供百度 SDK 的实际类型）、HTTPS 目标校验及连续人脸去重测试。尚未在本执行环境完成完整 Gradle APK 构建、签名校验和真机业务验收；不能把源代码编译检查当成 APK 已安装或已通过验票验收。

Windows 已连接真机时：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Build-Demo.ps1
if ($LASTEXITCODE -ne 0) { throw 'APP 构建失败，停止安装' }
powershell -ExecutionPolicy Bypass -File .\scripts\Test-Device.ps1 -Install
if ($LASTEXITCODE -ne 0) { throw '真机检查失败' }
```

`-VerifyJournal` 在独立测试数据库验证重启恢复、回执匹配、退出屏障和七天清理，不改当前账号的记录库。随后按 `docs/BINDING-TEST.md` 完成真人识别、活体、断网与换号验收。原 SDK、签名与授权文件不提交到仓库。

2026-10-13 通信修复：APP启动或保存HTTPS地址后独立上报设备通信，每15秒续报，无需先登录或完成SDK激活；原会话补传规则不变。后台展示登记授权码、APP上报授权码、SDK版本与授权结果。APP每页展示通信状态；只有收到平台响应才显示在线。手机进程停止/网络断开后，后台90秒超时显示离线。通信凭据持久保存，不随退出账号清空。

日常安装使用 `Test-Device.ps1 -Install`。`-VerifyJournal` 是可选的测试APK检查；手机需要允许该测试APK安装。用户提供的上轮日志显示正式APK已安装成功，测试APK被手机以 `INSTALL_FAILED_USER_RESTRICTED` 拒绝，不能据此认定业务测试通过。即使可选测试失败，脚本也先启动正式APP，再返回测试失败。

## 0.3.4 基础流程与百度设置

先更新配套平台，再覆盖安装。首页显示景区、设备、账号、规则、平台配置、人员/回执进度及最近同步时间。未取得完整平台信息、未完成同步或心跳过期时禁止开始核验。顶部“设置”直接打开百度原生 SettingActivity；平台地址仍由“平台连接设置”修改。

进入百度设置会暂停相机与SDK同步；返回后重新读取配置，检测最小人脸、检测阈值、质量阈值、RGB活体阈值、识别阈值可供当前核验链路使用，重新开相机时读取摄像头ID。当前手机采用RGB活体、系统相机方向；Demo中的红外/深度、镜像角度、图像优化、Demo日志等界面仍属原生能力，尚未全部接入本核验链路，不能把可打开等同于已生效。关闭Demo活体或质量开关不会取消本核验端的强制检查。返回后须手动开始核验。

修复SDK返回单位：512字节特征缓冲区对应128个float；旧代码误把成功返回128当成失败。本版保留真正的SDK异常返回值，不将其伪装成照片质量失败。

## 0.3.5 权限与同步减负

首次进入显示权限说明，可授权相机；所有页面保留权限管理入口。拒绝或系统不再询问时可跳转应用设置，统计与同步不依赖相机权限。平台照片不读取手机相册，不要求相册/全部文件权限。

空闲心跳15–20秒、通信30秒；有任务3–4秒继续，失败5–65秒退避错峰。已存储的同用户/同版本特征重新放入原生检索成功后直接确认，不重复下载照片；换版本或删除后不能复用。人员来自平台任务队列，目前为增量拉取，尚未实现长连接推送。先更新平台，再覆盖安装APP。更多容量验证待办见需求台账。

0.3.7：交替测试可点击“下一位 / 重新核验”；不同已录入身份稳定匹配可触发新一轮，同一人需移开或手动重试。诊断显示实际活体/识别分数，业务结果区分本地未匹配与平台拒绝。共享人员库在后续0.4.0实现，见下节。

## 0.4.0 共享人员库与本机记录

同平台退出重登、换账号或换景区保留人员特征，人员变更按增量同步；入园权限仍由平台按当前景区实时判定。首次从旧会话库升级会进行一次迁移核对，可能重新下载/提取，后续换号不再全量重建。更换平台地址会在原账号完整退出后重建该平台库。不要卸载或清除数据。

冷启动显示本地特征加载进度和用时，仍需要将SQLite特征装入SDK内存；20万条耗时尚未实测。新增本机今日记录/维护页，仅显示当前登录会话的本机结果与最近20条，景区全量数据请用景区入园统计。识别率调整按用户要求后置。数据库/手机新增回归测试待执行，详见需求台账。

## 0.5.0 管理员设置与蓝白界面

先部署配套平台，在“景区与设备 → 核验端管理员设置”配置独立密码，再覆盖安装APP。顶部管理员设置每次联网验证，后台只保存摘要；退到后台、退出设置或10分钟后重新锁定。原Demo参数模块由Apply-Demo恢复并检查完整性；当前终端业务使用RGB，其他原生模态并未自动接入。

界面加入蓝白主题、底部导航、独立同步与维护页面和结果弹窗，保留旧账号同步后退出。源码编译不代表真机验收；备份恢复、20万库实测和后台分批启动优化仍见需求台账待办。
