# APP维护配置（0.7.10-config，versionCode 129）

## 入口与权限

管理后台域名后访问 `/aapshezhilingluren`。无菜单入口。先登录平台管理账号，具备 `ykt:device:manage` 权限，再输入本次约定的专用访问密码。密码仅在服务端保存 bcrypt 校验值；解锁许可为 HttpOnly/Secure/SameSite=Strict Cookie，绑定当前登录会话，15分钟有效。密码错误限流。上传图片另需 `ykt:media:upload` 权限。入口隐藏不代替权限验证。

## 生效范围

- APP内名称、图标、首页副标题、页头背景、底部文字、公告：平台保存后APP启动检查，进程运行期间每30秒轮询；图片异步加载，失败保留默认背景并显示具体原因。离线沿用已缓存配置，不保证取得新配置。图片最多8MB，解码尺寸最多3200万像素并采样显示。
- 识别提示文字及语音：12类结果，与运营配置共用一份数据；同步心跳获取最新配置。平台关闭语音与手机本地静音同时有效。
- 全局封禁及最低版本：平台同时检查心跳与新的在线核验请求，APP显示具体封禁原因或最低版本。保留既有记录、失败记录补传和回执处理。单设备停用仍由设备管理控制。
- 更新检测：公告栏提示新版本，设备维护可手动检查，弹窗展示更新说明、最低版本、APK SHA256和HTTPS下载入口。版本按数字三段比较，构建后缀不参与大小比较。**不是离线推送或静默安装**；APP进程被系统终止时不能保证主动通知。浏览器下载不进行APP内SHA256自动校验，安装由Android系统确认。
- 桌面名称、图标：Android已安装应用无法从服务器任意改写Manifest。后台导出 `app-branding.json`，放入APP源码根目录，执行 `scripts/Export-Apk.ps1` 重新生成同包名、同签名APK，覆盖安装后生效。可先配置品牌再构建，将新APK上传后再填写发布版本和校验值。该JSON已gitignore，拉取及备份脚本不应清理它。Windows品牌脚本尚需实际构建验证。
- 图片使用公开媒体上传接口，不应上传授权码、人员照片或其他私密材料。
- 修改原因写入审计日志；APP配置版本与运营提示版本同时校验，旧页面保存冲突时保留编辑内容并要求重新读取。

## 设备识别

登录、激活、设备维护、诊断显示平台设备名称。首次取得本机授权备份后显示“已找到设备「名称」的算法授权”。名称与当前平台绑定缓存；尚未取得名称时说明需登录恢复并重试连接，不把手机型号冒充平台设备名称。后台设备列表与重装恢复窗口原有设备名称保留。

## 部署及验收顺序

1. 先部署本次配套平台代码，再构建并覆盖安装0.7.10-config；保留现有正式签名与本机数据。不要卸载测试升级。
2. 登录管理后台访问隐藏路径，验证错误密码拒绝、正确密码进入。非平台账号或缺少设备管理权限应拒绝。验证15分钟失效及退出登录后原许可不能复用。
3. 修改名称、图片、公告、12类提示中的测试文案，填写修改原因保存；手机检查30秒轮询及手动更新。
4. 两个管理员同时编辑，后保存者应收到配置版本冲突，售卡/价格等无关设置不变。
5. 测试用APK正式上传并验证下载后再发布版本。先验证更新提示，再提高最低版本，避免没有可用安装包却阻断全部设备。
6. 在测试设备验证全局封禁、恢复、单台停用相互独立；封禁后不能新增成功核验，原有未确认记录仍能补传取得回执。
7. 两台手机核对不同设备名称；重装恢复仅在确认无待确认记录且备份完成后验证。
