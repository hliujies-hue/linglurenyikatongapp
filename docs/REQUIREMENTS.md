# 需求基线 · 2026-10-13

## 已确认

- 应用名称一卡通景区刷脸核验端；包名 com.lingluren.yikatong.terminal。
- 首次仅显示设备激活、授权码填写；通过实际百度 SDK 联网一机一码认证，界面不显示厂商品牌。激活后方可登录。
- 平台后台开通账号密码，同一账号可登录 APP/网页；后端绑定景区及设备。授权码可在后台设备管理独立记录，仅平台人员可见。
- 不增加建库硬件。平台发图片，手机提取特征并本地检测、活体、搜索。目标 30 万有效用户，容量待真机验证。
- 平台不运行人脸算法，负责权益、共享次数、原子核验和日志。
- 同景区同人成功通过后 60 秒内不可再次通行；每次独立尝试仍记录。视频连续帧不能当作多次独立刷脸。
- 同景区当天：单点成功后其他设备拒绝；其他设备成功后单点拒绝。普通到普通按次数等规则执行。同台单点重复仍受次数规则限制。
- 设备类型、景区、账户和规则版本按事件发生时保存，不能因后续修改设备配置改写历史。
- 每次刷脸尝试完整留记录；同事件网络重传保留重传审计，不重复扣次、不计为用户新的尝试。
- 断网、平台超时不自动放行；工作人员现场手工记录，后台人工补录。
- 在线记录即时回传，正常目标一分钟内完成；平台持久化后自动逐条确认。
- 每七天一个清理节点，仅清理已满七天且已确认的本地记录。未确认永久保留直至确认后符合清理条件。
- 退出登录/更新/调拨不删除未确认记录。调拨后旧事件仍归原景区、原设备，并需要限定补传凭据。
- 拉黑、到期、退款无有效权益时优先清理人脸。续费退款若原权益仍有效，恢复权益而非误删。
- 清理后的人员统一提示未识别到有效用户；次数超限默认异常003。提示后台配置，固定内部状态码，语音默认跟随文字。
- 设备不提供详细刷脸记录/异常人员身份/抓拍照片查询，仅简单日期筛选、景区统一通过人数。
- 同景区所有设备与景区网页账号查询同一份人数，不累加设备去重人数。
- 旧硬件代码保留，不做本轮新功能兼容。
- 正式签名，本地构建安装；不自动触发 GitHub Actions。

## 未定项

- 人数日期范围展示为每天去重合计还是整个期间去重，以及结算周期，尚未最终确认。接口必须返回计数说明；不得自行定为每年一次。
- 单点设备当天自身重复次数按既有平台可配置规则，不能擅自改成永远仅一次。
- 30 万不同真实模板的性能、实际授权容量、手机机型、初始化耗时和温升阈值需要现场验收。

当前提交是 APP 开发首批，不是营业交付。平台接口、后端并发事务、权限及管理员配置页面仍待开发。开发版锁定正式通行入口。
