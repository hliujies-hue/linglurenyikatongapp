## Windows更新与安装流程

使用交付消息中的完整提交SHA，保留C:\Users\Administrator\Desktop\app现有Demo与原签名。按顺序执行：SSH fetch指定提交、确认本地修改、快进至指定提交、Verify-Release.ps1 -Revision <提交SHA>、Export-Apk.ps1、Test-Device.ps1 -Install。完整复制命令随提交SHA交付。

Export-Apk默认运行主机测试、release构建和Lint，不使用-DeferTests。任一步失败停止；禁止安装之前残留的旧APK。覆盖安装不卸载、不清除数据。正式APK导出到桌面Yikatong-APK，新目录内build-info.txt记录版本、源码和SHA256。

## 真机验收顺序

1. 空闲测试机覆盖安装后，诊断显示139/0.7.20；确认原授权、人员库和账号仍在。
2. 进入“人员同步→重新验证当前账号”，错误密码应失败且保留记录；正确密码应恢复同步，待平台确认后才允许开始核验。
3. 测试账号凭证失效时，刷脸/统计显示登录失效；断网应显示连接故障，不能误提示密码失效。
4. 有待确认记录时恢复账号，确认后台仅一条对应记录，不重复播报已通过结果；双方序号/回执一致。
5. 同步退出期间分别在PAUSING/DRAINING恢复凭证，继续原退出流程，不重新绑定或清空记录。
6. 进程重启、前后摄切换、关闭验证窗口后响应返回，确认无异常跳页与误放行。
7. 可选独立数据库测试：scripts/Test-Device.ps1 -VerifyJournal。只在空闲测试机执行；这不是业务或真人准确性验收。
