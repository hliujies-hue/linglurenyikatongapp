# 算法授权保存与卸载重装恢复（0.7.7-license / 126）

首次激活仍需要本机算法授权码。以后正常启动、同签名覆盖更新会自动读取保存的授权；卸载重装后登录原景区启用的工作人员子账号，APP 会自动向平台取回本机备份，再调用真实算法组件校验。工作人员无需重复抄写授权码。

## 使用顺序

1. 先部署本次配套平台，再构建并覆盖安装 APP。沿用正式签名，不要卸载旧版来更新。
2. 打开 APP，等待本机授权自动校验；完成景区账号登录。
3. 在“设备诊断”确认“算法授权备份：算法授权码已备份到当前平台”。若提示待重试，点击检查连接，按具体错误处理。首次激活后尚未登录景区的设备不具备账号归属验证条件。
4. 误卸载后重新安装同一正式签名、相同包名的 APP，连接原平台，直接登录原景区启用的子账号。授权码恢复成功后继续登录，不显示恢复得到的授权码。
5. 若提示原会话/本地人员库标识已变化，由平台管理员按现有“重装恢复”流程确认本机记录丢失风险。授权恢复不会替管理员废弃旧会话；管理员处理后再次登录即可，无需重新填算法授权码。

正常换账号继续使用“同步退出”，不能通过卸载替代待确认记录补传。正常升级请覆盖安装；本功能无法找回卸载前未上传的记录或已删除的人脸特征，人员库需按现有流程重新同步。

## 明确的异常提示

| 情况 | 处理 |
|---|---|
| 平台未找到本机登记 | 确认连接原平台、正式签名、系统用户；新设备走首次激活 |
| 原设备尚未归属景区 | 请管理员核对本机授权与设备归属，不能向任意账号下发授权码 |
| 当前账号属于其他景区 | 使用原景区启用的子账号；跨景区调拨交管理员处理 |
| 平台没有可用备份 | 管理员在设备配置中补录本机算法授权码；手机再次登录取回，无需在手机重复输入 |
| 平台授权备份解密失败 | 核对原加密配置和备份，保留设备档案；不把解密失败当作无授权 |
| 平台未提供恢复接口 | 先更新配套平台 |
| 算法授权校验失败 | 显示组件错误码及具体原因，不能仅凭平台有备份就允许核验 |
| 算法已校验但本机保存失败（-2003） | 检查存储空间后重试，避免宣称持久保存完成 |

## 实现边界

- 本地成功码使用同步提交的私有存储，并兼容旧版本 `activate_online_key`；不删除原算法授权文件。原授权组件在文件完整且匹配时读取本地授权文件。
- 平台沿用加密授权字段，无新增表结构。只有成功授权上报才能写入上报码；失败、校验中和未授权上报不会覆盖成功码。
- 恢复接口为 `POST /api/terminal/license/restore`，在登录认证路由组内，校验启用子账号、主账号/景区、设备状态和景区一致性；返回禁止缓存，审计不写授权码/指纹/令牌。
- 恢复接口不修改设备通信凭据、业务会话、代次或核验就绪状态；仍必须经过真实算法授权和原有登录、同步、平台实时核验。
- 更新/重装需保持包名、签名、系统用户与设备身份。更换硬件、刷机、恢复出厂或算法版本改变造成指纹变化时，不承诺旧授权可用，也不伪造指纹或绕过授权服务。
- 产品激活页、错误、诊断、管理员设置入口与页脚、后台授权字段统一算法术语。保留依赖包名、接口标识和必要源码技术信息。

## 验收清单

同签名覆盖更新不输入授权码；重启不输入；误卸载后正常登录自动恢复；恢复失败不建立可核验会话；不同景区账号/停用设备/过期登录不能取回授权；错误码重试不污染成功备份；界面旋转或切回前台不重复发起激活；旧会话恢复后人员重新同步。

Android 官方说明 `ANDROID_ID` 与签名、设备及系统用户相关，同签名卸载重装通常保持，但存在系统升级历史等例外：https://developer.android.com/about/versions/oreo/android-8.0-changes#privacy-all 。算法授权以组件实际取得的设备指纹及校验结果为准。
