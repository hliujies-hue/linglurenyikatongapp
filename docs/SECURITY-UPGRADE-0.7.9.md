# 0.7.9 安全升级验收

先更新配套平台，再覆盖安装 APK，禁止先卸载。平台与后台应一起更新，后台刷新后重新登录。

## 操作步骤

1. 当前设备先同步未确认入园记录；在维护页备份未确认记录（保管备份密码）。不要删除现有数据或正式签名。
2. 覆盖安装后保持应用运行，首次加密迁移显示类别和已处理编号；断电后重启按事务检查点续迁。完成后验证账号、算法授权、本地人数及待确认记录数量。迁移后不能直接安装旧版读取数据库。
3. 执行 `pwsh -NoProfile -File .\scripts\Test-Device.ps1 -VerifyJournal`；多台设备添加 `-Serial '手机序列号'`。脚本会构建测试 APK，使用隔离测试数据库验证旧版迁移、记录回执、特征加密和续迁。失败必须留存输出，不能当成已验收。
4. 验证真实人脸、活体、识别拒绝、断网补传、重启恢复、同步退出后换账号；弱网期间预览应继续，平台未确认时不得显示通行。
5. 浏览器测试登录、刷新、退出、导出、权限拒绝、多标签页换号。开发者工具检查 Cookie 的 Secure/HttpOnly/SameSite=Strict，确认 Local Storage 不再保存 JWT；旧标签页操作必须提示账号切换。

## 当前证据与边界

生产 Java 和仪器测试源码已编译，主机加密/队列测试已执行；仪器测试必须在 Android 执行，不能由主机模拟替代。0.7.8 的成功安装记录不代表 0.7.9 已部署。Android 21/22 的 RSA 封装兼容路径尚未真机验证。会话、人员特征、事件与设备配置加密；索引编号、时间、结果分类以及 SDK 自有授权缓存不属于全库密文。密钥损坏时保留原数据并停止业务，不自动删除人员库或待上传记录。SQLite 清理不等于保证闪存历史块无法恢复。

后台仅正式 HTTPS 域名 https://yktadmin.qiliai.com 通过浏览器来源校验；后端接口仍为现有平台地址。端点 Cookie 为主机专属，不开放任意域名凭据 CORS。
